# ASA College eLearning Platform — Stakeholder Analysis & Requirements

## 1. Stakeholder Register

| Stakeholder | Needs | Potential pain points |
|---|---|---|
| Students | Course materials, timetables, announcements, assignment submissions and grades | Difficulty finding information and tracking deadlines |
| Lecturers | Upload resources, manage assignments, grade work and communicate with students | Repetitive administration and fragmented communication |
| Administrators | Manage student records, enrolments and requests | Manual data entry and duplicate records |
| Management | Reports and academic performance indicators | Delayed reporting and limited visibility |
| IT Staff | Secure access, backups, monitoring and troubleshooting | Downtime, security issues and integration challenges |

## 2. Functional Requirements

| ID | Requirement | Priority |
|---|---|---|
| FR-01 | The system shall authenticate authorised users. | Must have |
| FR-02 | Students shall access their enrolled courses and learning resources. | Must have |
| FR-03 | Lecturers shall upload course materials and announcements. | Must have |
| FR-04 | Students shall submit assignments and receive confirmation. | Must have |
| FR-05 | Lecturers shall manage assignments, grades and feedback. | Must have |
| FR-06 | Administrators shall manage authorised student records. | Must have |
| FR-07 | The system shall enforce role-based permissions. | Must have |
| FR-08 | Management shall access authorised reports. | Should have |
| FR-09 | Users shall receive relevant announcements and deadline notifications. | Should have |
| FR-10 | IT staff shall review activity logs and manage access. | Must have |

## 3. Non-Functional Requirements

| ID | Requirement | Proposed target |
|---|---|---|
| NFR-01 | Security | Secure authentication and access controls |
| NFR-02 | Performance | Standard pages load within 3 seconds under an agreed test load |
| NFR-03 | Availability | Proposed 99.5% monthly availability |
| NFR-04 | Usability | Common tasks can be completed without extensive training |
| NFR-05 | Accessibility | Target WCAG 2.2 Level AA |
| NFR-06 | Privacy | Protect personal information and restrict access |
| NFR-07 | Compatibility | Support agreed desktop and mobile browsers |
| NFR-08 | Recovery | Document and test backup and recovery procedures |

## 4. Stakeholder Needs and Pain Points

- Students need easy access to learning materials and clear assignment deadlines.
- Lecturers need efficient course and assessment management.
- Administrators need accurate records and streamlined workflows.
- Management needs timely, reliable reports.
- IT staff need secure, reliable and maintainable systems.

These pain points are initial assumptions and require stakeholder validation.

## 5. Assumptions Requiring Confirmation from ASA

1. Which existing LMS and student management systems are used?
2. What login and authentication methods are required?
3. What access permissions apply to each user role?
4. How many users must the system support?
5. What privacy, security and data retention policies apply?
6. What reports does management need?
7. What performance, availability and recovery targets are required?
8. What budget, delivery timeline and technology constraints apply?

## 6. Conclusion

The proposed ASA College eLearning Platform should provide centralised learning resources, efficient academic workflows, secure information management and useful reporting. All proposed requirements and targets must be validated with ASA before implementation.
